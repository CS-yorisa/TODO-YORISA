# 페이지 레이아웃 문서 업데이트

templates 디렉토리와 urls.py 파일을 분석하여 `docs/page-layouts.md`를 최신 상태로 업데이트합니다.

## 실행 절차

### 1단계: 정보 수집

다음 파일들을 모두 읽어서 현재 페이지 정보를 수집한다.

1. **URL 설정 파일**: 프로젝트 레벨 `yorisa/urls.py`와 각 앱의 `urls.py`를 읽어 등록된 URL 패턴을 파악한다.
2. **페이지 템플릿**: `templates/` 하위의 모든 `.html` 파일을 읽는다. (`templates/<app>/components/`, `templates/components/` 디렉토리의 파셜 템플릿 포함)
3. **CSS 파일**: `static/css/` 하위의 CSS 파일에서 CSS 변수(`:root`)와 미디어 쿼리 브레이크포인트를 파악한다.

### 2단계: 페이지별 정보 분석

수집한 정보를 기반으로, 각 페이지 템플릿에서 다음을 분석한다.

- **URL**: urls.py에서 해당 템플릿을 렌더링하는 URL 패턴
- **뷰**: 해당 URL에 매핑된 뷰 함수/클래스와 위치 (파일명 > 함수명)
- **템플릿 경로**: 메인 템플릿 파일 경로
- **파셜 목록**: `{% include %}` 또는 HTMX `hx-get`/`hx-post`로 연결된 파셜 템플릿 경로
- **섹션 구성**: 템플릿 내의 `<section>`, `<header>`, `<footer>` 등 주요 시맨틱 태그를 기준으로 섹션 목록과 각 섹션의 역할을 정리
- **HTMX 사용**: `hx-get`, `hx-post`, `hx-target`, `hx-swap` 등 HTMX 속성이 사용된 부분을 정리 (엔드포인트, 대상 요소, 파셜 템플릿 매핑)

### 3단계: 문서 작성

분석 결과를 아래 형식에 맞춰 `docs/page-layouts.md`를 **전체 다시 작성**한다.

```markdown
# 페이지 레이아웃

각 페이지의 URL, 템플릿 경로, 섹션 구성, 사용된 HTMX 패턴을 정리합니다.

---

## {페이지 이름}

{페이지에 대한 한 줄 설명}

- URL: `{url}`
- 뷰: `{파일명}` > `{함수/클래스명}`
- 템플릿: `{경로}`
- 파셜: `{파셜 경로 목록}` (없으면 이 줄 생략)

### 섹션 구성

| 순서 | 섹션 | 설명 |
|------|------|------|
| 1 | {섹션명} | {설명} |

### HTMX 사용

(HTMX를 사용하지 않는 페이지는 이 섹션 생략)

| 동작 | 엔드포인트 | 파셜 템플릿 |
|------|-----------|-------------|
| {동작 설명} | `{METHOD} {url}` | `{파셜 경로}` |

---

## {다음 페이지 이름}

...
```

### 4단계: 디자인 테마 섹션

문서 마지막에 공통 디자인 테마 정보를 한 번만 작성한다.

```markdown
---

## 공통 디자인 테마

| CSS 변수 | 색상 | 용도 |
|----------|------|------|
| ... | ... | ... |

반응형: ...
```

### 주의사항

- `docs/page-layouts.md` 파일은 항상 **전체를 새로 작성**한다. 기존 내용에 부분 추가하지 않는다.
- 페이지 순서는 urls.py에 정의된 순서를 따른다.
- `components/` 디렉토리의 파셜은 독립 페이지가 아니므로, 해당 파셜을 사용하는 페이지 하위에 기록한다.
- admin 페이지(`/admin/`)는 문서에 포함하지 않는다.
